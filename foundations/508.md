# Section 508 Data Visualization Requirements

All data visualizations shared publicly on the web by the U.S. Census Bureau must meet federal Section 508 mandates. Our technical baseline aligns directly with the World Wide Web Consortium (W3C) [Web Content Accessibility Guidelines (WCAG) 2.1 Level AA Standards](https://www.w3.org/WAI/WCAG21/quickref/).

---

## 1. Alternative Text (Alt Text)

All digital graphic elements representing data must include short, descriptive alternative text embedded in the source markup. 

* **Required Formula:** State the chart type, the target population variables, the geographic/time boundaries, and the primary statistical trend or takeaway.
* **Character Limit:** Keep short alternative descriptions under 250 characters. If a visualization is too complex to summarize within this constraint, developers must provide a parallel structured data alternative.

---

## 2. Accessible Data Tables

To convey the full analytical depth of a visual chart to users navigating with assistive technology, visually complex charts, scatter plots, maps, and graphs must be paired with an immediately adjacent, structured HTML data table.

* **Coding Standards:** Tables must use semantic markup, including designated table rows (`<tr>`), explicitly defined column headers (`<th scope="col">`), and data rows (`<td>`) to ensure clear matrix tracking for screen readers.
* **Technical Inquiries:** For structural assistance or validation reviews, contact the Census Bureau Section 508 Program Office at [census.508.accessibility@census.gov](mailto:census.508.accessibility@census.gov).

---

## 3. Responsive Text and Media Scaling

To ensure users with low vision can effectively consume graphical reporting, all text layers, visual charts, and embedded components must remain fully operable when zoomed or magnified.

* **Sizing Guardrails:** Content, labels, and graphic assets must scale seamlessly up to 200 percent using standard browser magnification tools without losing structural layout context, text clipping, or baseline interactive functionality.

---

## 4. Color Contrast and Multi-Layer Encoding

Visual data design requires strict color parameters to guarantee legibility for individuals with color vision deficiencies or low visual acuity.

* **Contrast Ratios:** Static text, axis indicators, and interactive layout assets must maintain a minimum contrast ratio of **4.5:1** against the background canvas. Adjacent, distinct visual data marks (such as separate lines on a trend graph) must maintain a minimum contrast ratio of **3:1** against each other.
* **Redundant Encoding:** Color must never serve as the exclusive mechanism to communicate data classifications, grouping structures, or trend values. Developers must incorporate secondary graphic identifiers, such as distinct stroke patterns, varied shape markers, or direct labels. For detailed design rules, see the [W3C WCAG 2.1 Color Contrast Requirements](https://w3.org).
